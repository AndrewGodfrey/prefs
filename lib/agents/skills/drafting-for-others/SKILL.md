---
name: drafting-for-others
description: Use when drafting text the user will send to another person — a note to a co-contributor,
  a team question, a work-item or PR description. Not for content addressed to the user themselves.
---

Simplify the wording to the essential. Cut mechanism the reader doesn't need explained.

Open with what the reader needs to act on: the conclusion, its impact, and how confident we are. Put evidence after it.
This applies again to every later edit. Investigation findings tend to get appended over time, so after each edit
re-read the opening as a newcomer would, and rewrite it if it no longer states the current conclusion.

For each factual claim, attach a code pointer hosted somewhere the reader can access, e.g.
`[class Foo](url)`. These pointers are "evidentiary", i.e. cheap to verify. This is important for
a) the user, to verify before sending, and b) the reader, so they can cheaply verify and follow the
argument. Check skills for cheap ways to generate these urls (the mechanism depends on the
environment).
